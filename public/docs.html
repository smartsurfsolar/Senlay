Senlay API and MCP documentation

Overview

Evaluation beta. Commercial Open-Meteo access has not been arranged. Confirm commercial source rights and configuration before commercial deployment; actual availability depends on current deployment settings. The API is not flight or mission clearance.

Senlay is a physical-world intelligence infrastructure beta for autonomous systems, robotics and AI applications. It returns available environmental observations, model values and contextual evidence for a coordinate, including provenance, timestamps, distance, disagreement and uncertainty where available. SmartSurf is the product origin and reference application. Begin with the robotics integration overview for current capability boundaries. Each request depends on the sources available at its coordinate.

The Physical World Model (PWM) returns available environmental evidence for a coordinate. The catalog lists 23 source-family entries; entries are adapters or provider families, not a count of live sources at a coordinate. Actual configured, returned, and unavailable sources are reported separately.

The Senlay layer stack adds a versioned catalog for live sensors, forecast models, terrain elevation, satellite visual context, hazards, and risk operations, plus planned bathymetry, land cover/roughness, buildings/obstacles, coastline/access, and telemetry layers. Runtime status explicitly distinguishes active data from layers that are not loaded. Heavy static layers require background preprocessing and compact cached spot summaries.

For developer workflows, the response can include a pre-formatted context_string with available evidence and limits. Pass it to an LLM as data/tool output under your application's instructions. For workflows such as SmartSurf, Senlay can also produce risk_event records for alertable and auditable operational context.

Measured observations vs. predictions. METAR stations, ocean buoys, and tide gauges produce measured readings. Weather models produce predicted values. When they disagree, Senlay reports the available values and relevant freshness, distance, data quality, and uncertainty; an instrument reading is not automatically ground truth.

Robotics telemetry examples. The project includes read only reference adapters for CRC-checked MAVLink 1/2 position frames over UDP and ROS 2 sensor_msgs/msg/NavSatFix through rosbridge. They use the existing authenticated GET /api/v1/pwm endpoint and do not issue robot commands. ROS 2 and rosbridge are separate prerequisites; the examples do not convert local-coordinate messages, authenticate MAVLink senders, evaluate routes, or provide safety clearance. See the adapter details and limits.

Run the synthetic robotics example

Node.js 22; no npm install. Download senlay-robotics-v0.1.0.zip, then run:

unzip senlay-robotics-v0.1.0.zip
cd senlay-robotics-v0.1.0
node examples/robotics/robotics-context.mjs --transport replay

The replay position and environmental values are synthetic, with no key, network, hardware or robot commands. For live MAVLink UDP or ROS 2 rosbridge, follow the bundled README and transport requirements, shared API limits and capability boundaries.

Direct answers for agents and developers

What endpoint should an agent call?Use /api/v1/try-sense for a no-key browser trial, /api/v1/sense for authenticated plain text, and /api/v1/pwm for structured JSON.
What parameters are required?lat and lng are required. field and request improve domain interpretation.
What does the response contain?Measured/model conditions, source evidence, freshness, confidence, disagreement, decision_context, modifiers, and context_string.
How do safety apps consume alerts?Use /api/v1/risk-events and /api/v1/risk-events/recent for operational risk records suitable for SmartSurf-style station, lifeguard, and audit workflows.
How do agents inspect the layer stack?Use /api/v1/layers/catalog for provider/layer metadata and /api/v1/layers/context for a coordinate-specific layer context.
What happens when data is missing?Senlay returns the available context and should expose uncertainty. Agents should not invent missing measurements.
How should an LLM use context_string?Pass it as data/tool output under the application's instructions. Preserve source, time, distance, disagreement, and unknowns. It is decision support, not flight or mission clearance.

Provenance & Evidence

Current PWM responses expose provenance across fields such as current_source, source_use, per-layer source labels, timestamps, modifiers, and decision context. The example below is a synthetic concept sketch, not a current response schema or a promise that every field is returned.

Evidence-shaped context_string

The pre-formatted context_string summarizes available evidence. This synthetic wind illustration is not live data and does not establish a trend:

Example context_string 
SYNTHETIC EXAMPLE — NOT CURRENT DATA
At 2026-01-15 12:00 UTC, a sample station 4.2 km away reports
wind at 18 km/h; a model value for the same valid time is 12 km/h.
The values differ by 6 km/h. Check timestamps, calibration, and
representativeness. A single comparison does not establish a trend.

Authentication

Authenticated API endpoints require a Bearer token. The public /api/v1/try-sense endpoint is a limited no-key trial for browser-based chat agents.

HTTP Header 
Authorization: Bearer sl_live_your_key_here

See current beta access and limits, then create an account and API key for authenticated requests. A key does not grant commercial source rights.

Quick Start

For a drone wind evidence review, request the wind profile explicitly. This example reports the HTTP status before interpreting a response; a non-2xx response is an API error, not evidence.

Python requests 
import os
import requests

url = "https://senlay.cloud/api/v1/pwm"
params = {"lat": 37.6213, "lng": -122.3790, "field": "drone", "profile": "wind"}
response = requests.get(url, params=params, headers={"Authorization": f"Bearer {os.environ['SENLAY_API_KEY']}"}, timeout=20)
print("HTTP", response.status_code)
if not response.ok:
    raise RuntimeError(f"Senlay API error {response.status_code}: {response.text}")
data = response.json()
assessment = data.get("risk_assessment", {})
print("outcome:", assessment.get("outcome", data.get("outcome")))
print("evaluation_scope:", assessment.get("evaluation_scope", data.get("evaluation_scope")))
print("unknowns:", assessment.get("unknowns", data.get("unknowns", [])))
for layer_name, layer in data.get("pwm", {}).get("layers", {}).items():
    source = layer.get("current_source") or {}
    print(layer_name, source.get("source"), source.get("timestamp"), source.get("distance_km"))

MCP Server

Connect an MCP-capable agent directly to https://senlay.cloud/mcp. Anonymous evaluation access needs no installation, account, or OAuth flow. Add an optional Senlay API key as a Bearer header to use the key owner's published beta allowance. The four tools are sense_location, check_operability, list_domains, and get_forecast_trust.

MCP client configuration 
{
  "mcpServers": {
    "senlay": {
      "url": "https://senlay.cloud/mcp"
    }
  }
}

The server uses stateless Streamable HTTP. The MCP SDK negotiates a compatible protocol version during initialize; clients should not rely on a fixed version in health metadata. It exposes four tools:

ToolPurpose
sense_locationEvidence and provenance for current physical conditions, including source distance, age, measured/predicted status, confidence, divergence, and unavailable evidence.
check_operabilityDomain-specific deterministic risk events, thresholds, exceeded conditions, unknowns, and assessment uncertainty. Decision support only; humans remain the final authority.
list_domainsStatic list of supported operational domains and a brief of their evidence/threshold logic.
get_forecast_trustHistorical forecast reliability by wind speed and direction; returns UNKNOWN until eligible archived forecast and instrument pairs are sufficient.

For authenticated use, configure the same URL with Authorization: Bearer sl_live_your_key. Treat historical forecast trust as UNKNOWN unless the response establishes it. Anonymous limits return a direct link to POST /api/v1/agent-register. The optional time input currently accepts only present-time requests; historical and future requests fail explicitly rather than being silently treated as current.

GET /api/v1/try-sense

Public, no-key evaluation endpoint for chat agents with browsing. It returns plain text, includes usage guidance, and is rate-limited. Use it to inspect currently available source context; coverage and freshness vary, and a response may contain gaps or no usable observation.

GET URL 
https://senlay.cloud/api/v1/try-sense?lat=36.01&lng=-5.60&field=drone&agentName=MyChatAgent

Parameters

ParameterRequiredDescription
latYesLatitude (-90 to 90)
lngYesLongitude (-180 to 180)
fieldNoReasoning mode, for example kitesurfing, drone, sailing, agriculture, running, or general
agentNameNoHuman-readable name shown in the trial response
requestNoAgent/user task embedded into the response so the model can answer with the correct field context
viewNoUse view=live to open the self-updating HTML page instead of the plaintext response

The same live page is also available at /agents/live. It stores state in the URL, so parallel agents can use different agentName, field, request, and session values without overwriting each other.

Trial mode is intentionally limited: 8 requests/minute burst and 60 requests/hour per IP. The live page clamps automatic refresh to 120-600 seconds. For repeated use or automation, register an agent and use /api/v1/sense with Bearer auth.

GET /api/v1/layers/catalog and /api/v1/layers/context

The layer endpoints expose the product-level stack that Senlay uses to explain current and planned physical-world context. Public demo equivalents are available at /api/layers/catalog and /api/layers/context; authenticated API clients should use the /api/v1 paths with a Bearer key.

Layer catalog

curl 
curl -H "Authorization: Bearer sl_live_your_key" \
  "https://senlay.cloud/api/v1/layers/catalog"

Returns layer metadata, recommended providers, status, cadence, license notes, output fields, and the request-time policy. The catalog includes active runtime providers and planned static providers; each entry states its access and deployment status. Open-Meteo layers are conditional on a paid customer key or compliant configured host; OpenAQ v3 and NASA FIRMS also require credentials. Heavy sources such as GEBCO and WorldCover remain planned until preprocessed and loaded. Even when loaded, the coarse GEBCO grid can provide regional depth/gradient context but cannot identify spot-scale reefs, sandbars, or obstructions and is not a navigation chart.

Spot layer context

curl 
curl -H "Authorization: Bearer sl_live_your_key" \
  "https://senlay.cloud/api/v1/layers/context?lat=36.0143&lng=-5.6044&field=kitesurfing"

Returns the current coordinate-specific layer status plus derived terrain, marine, wind, sensor, and risk context. Missing heavy layers are reported as next actions instead of being loaded synchronously.

GET /api/v1/sense

Simplified endpoint — returns only the context_string as plain text. Content-Type: text/plain. Ideal for agents that don't want to parse JSON.

Parameters

Requires lat and lng; optional field selects the reasoning mode. profile is supported by /api/v1/pwm, not this plain-text endpoint.

curl 
curl -H "Authorization: Bearer sl_live_your_key" \
  "https://senlay.cloud/api/v1/sense?lat=36.01&lng=-5.60&field=drone"

Returns the Physical World Model as a plain text block. No parsing is required. Pass it as data/tool output under your application's instructions, preserve source and uncertainty, and do not treat it as clearance for physical action.

GET /api/v1/risk-events

Authenticated endpoint for operational risk events. Use it when an application needs more than context text: a station dashboard, lifeguard workflow, fleet monitor, school safety view, or IoT alert pipeline can read structured events that summarize the detected risk, severity, coordinates, sources, and recommended review path.

SmartSurf is the first proving ground: Traccar GPS movement and local triggers identify a possible rider or board problem, then Senlay adds environmental evidence before the system escalates or stays quiet. The endpoint is decision support, not a certified rescue authority.

Risk responses can also include risk_assessment: an aggregate deterministic state with score, alert band, confidence, reasons, recommended action, escalation stage, incident state, source provenance, session phase, and field-validation metadata. This is the SmartSurf early-warning contract: it is meant to show recoverability risk and coordination needs, not to diagnose drowning or claim rescue dispatch.

risk_assessment.outcome is one of GO, CAUTION, NO_GO, or INSUFFICIENT_EVIDENCE. The last one is a normal, successful result (HTTP 200), not an error: it means the evidence does not support a verdict, and risk_assessment.unknowns names the specific blocking variable(s), why (no coverage, sources conflict, stale, or missing entirely), and what would resolve it. Confidence is also decomposed into risk_assessment.confidence_components — source_agreement, freshness, spatial_relevance, and evidence_coverage — each with its own label and reason string, rather than one blended score. When hardware and model sources disagree, the disagreement is reported as a structured risk_assessment.conflicts entry (each contributing source's value, distance, and age, plus the delta and magnitude) instead of being averaged away.

POST /api/v1/agent-register

Dedicated registration for AI agents — no password needed. Only agentName is required. The first response displays an API key and recovery token once. If you supply ownerEmail, the (ownerEmail, agentName) pair becomes a stable identity: a later request must include the current recovery token and rotates both credentials instead of revealing the old API key.

curl — minimum 
curl -X POST https://senlay.cloud/api/v1/agent-register \
  -H "Content-Type: application/json" \
  -d '{"agentName": "MyAgent"}'
curl — recommended (stable agent identity) 
curl -X POST https://senlay.cloud/api/v1/agent-register \
  -H "Content-Type: application/json" \
  -d '{"ownerEmail": "your_real_email@domain.com", "agentName": "MyAgent"}'

Request Body

FieldRequiredDescription
agentNameYesAgent identity, min 2 chars
ownerEmailNoOwner's real email. Creates a stable identity that can rotate credentials with its recovery token. If omitted, every call creates a fresh agent.
recoveryTokenOnly for rotationThe current one-time-issued recovery credential for an existing (ownerEmail, agentName) identity. A successful rotation invalidates the previous API key and recovery token.

Response

JSON 
{
  "success": true,
  "apiKey": "sl_live_xxxxxxxxxxxxxxxx",
  "keyPreview": "sl_live_xxxx…xxxx",
  "recoveryToken": "sl_recover_xxxxxxxxxxxxxxxx",
  "agentName": "MyAgent",
  "existing": false,
  "rotated": false,
  "message": "Save the API key and recovery token now; neither is shown again."
}

Store both secrets outside logs and source control. For an existing identity, send the current recoveryToken; a successful response has existing: true and rotated: true, and returns new credentials. The old API key stops working.

POST /api/v1/agent-lookup

Discover agents associated with the signed-in owner's email address. This route requires a valid Senlay account session and a verified sign-in identity whose email exactly matches ownerEmail; password-only accounts remain fail-closed until an explicit verification/link flow exists. It returns masked key metadata only. Full keys and recovery tokens are never returned. If an API key is lost but you kept the recovery token, rotate the credentials through /api/v1/agent-register. If both secrets are lost, contact support. Rate-limited to 20 lookups/hour per signed-in user.

  -d '{"ownerEmail": "your_real_email@domain.com"}'

Data Sources

The sensor catalog contains 23 source-family entries. This is not a claim that all sources are configured or available at a coordinate. The API returns the available context and marks gaps or uncertainty where needed.

Open-Meteo deployment note: its free hosted API is for non-commercial use. Commercial deployments must use the paid customer-api.open-meteo.com endpoint with an API key, or a compliant self-hosted service. Open-Meteo data attribution is required. Review the current terms and commercial configuration before deployment.

Windy deployment note: Stations and Webcams are separate products with separate credentials. Open-station access is governed by the current Windy Stations terms and Aggregator Open Data Licence. Confirm that the configured agreement permits the intended use; preserve required operator credits and show Windy's Add new station link with presented station data.

Windguru deployment note: Senlay uses Windguru's documented Station JSON API, which requires the station ID/UID and that station's API password or hash. Public station pages are not treated as an anonymous redistribution API. The adapter remains disabled until the owner credential and permission for Senlay's intended use are recorded; secrets stay server-side.

Client REST helper example

Python 
import os
import requests

def fetch_drone_wind_evidence(lat, lng):
    """Return available wind evidence for human operator review."""
    response = requests.get(
        "https://senlay.cloud/api/v1/pwm",
        params={"lat": lat, "lng": lng, "field": "drone", "profile": "wind"},
        headers={"Authorization": f"Bearer {os.environ['SENLAY_API_KEY']}"},
        timeout=20,
    )
    response.raise_for_status()
    return response.json()  # Keep the source metadata and unknowns

Understanding the PWM

The context_string

This pre-formatted text block summarizes available sensor/model data, provenance, and explicit gaps. No JSON parsing is required, but pass it as data or tool output under your application's instructions; do not let returned text override system or safety instructions. Preserve source, freshness, disagreement, and uncertainty. It does not authorize flight, mission, or other physical action.

HARDWARE vs MODEL

Direct observation records can include an is_hardware boolean. Official alerts, event catalogs, satellite products, and some provider summaries are separate feed types and must not be relabeled as local hardware measurements.

  • is_hardware: true — physical sensor measurement (METAR station, ocean buoy, tide gauge)
  • is_hardware: false — computer model forecast/estimate

Hardware readings are measured observations; models are predictions. When they disagree, inspect each source’s freshness, distance, calibration, and representativeness — subject to freshness, distance from the query location, station calibration, and contextual relevance. Senlay surfaces those dimensions rather than asserting ground truth.

Cross-referencing

When multiple wind sensors are available, Senlay calculates:

  • wind_cross_reference.average_kmh — average across the accepted, valid, physically distinct comparison stations
  • wind_cross_reference.min_kmh / max_kmh — range
  • wind_cross_reference.confidence — "high" (3+ sensors agree) or "moderate" (2 sensors)

Rate Limits

Senlay is currently in open beta. Each free account has a shared allowance of 100 authenticated API calls per day across all of its active keys. The daily allowance is shared across keys. Request allowance and source refresh capacity are separate: cache hits can count as authenticated requests without requiring a new source refresh. Some rejected pre-fetch requests are refunded; attempted upstream failures are not generally refundable. Adapters should use the documented default 120-second cadence unless a scoped agreement sets another interval.

For details on future plans and pricing, see the Pricing page.

What a verification request attempts

  • Configured model layers for atmosphere, hydrosphere, terrain, and air quality; any layer may be unavailable, disabled, outside coverage, or fail independently
  • Extended hardware, hazard, satellite, and community source checks where coverage and provider terms allow
  • Early Modifier Engine — working demos of physics-based calculators (terrain-wind hints, wave modifiers, gust-factor analysis, ET0, orographic effects). Deeper validated models under development.
  • Pre-formatted context_string for optional model explanation under application instructions
  • Per-source health reporting so clients can distinguish returned data from unavailable, disabled, no-data, or failed sources

Verification Glossary

These are the terms used across Senlay and SmartSurf. They are linked from the site footer and product pages so agents, riders, schools, and developers can check exactly what each word means.

Evidence Object v1

The planned structured contract for each claim in a Senlay response. It keeps the value, unit, source, timestamp, distance, freshness, confidence, uncertainty, and disagreement visible instead of hiding them in a generic answer.

Source provenance

The trace of where a value came from: station, model, buoy, METAR, satellite, device telemetry, private sensor, or derived local rule. Provenance lets an app explain how it knows something.

Freshness

How recent a measurement or model run is. A nearby stale sensor can be less useful than a fresher alternate source, so Senlay surfaces freshness instead of treating all values equally.

Confidence

A decision-support signal based on source quality, distance, freshness, source agreement, and local domain fit. Confidence is not a guarantee of safety.

Uncertainty

The visible limits of the current answer: missing sensors, stale data, disagreement, weak local coverage, or conditions changing faster than sources update.

Model-vs-reality check

Comparison between forecast/model values and live observations. For SmartSurf, this helps decide whether a generic forecast matches what is happening at the beach or on the water.

risk_event

A structured safety workflow record. It can represent rider stopped, board separated, offshore drift, low-confidence no-go, or other alertable states for SmartSurf-style dashboards.

Decision-support boundary

Senlay and SmartSurf support decisions; they do not replace instructors, local judgment, official rescue services, weather authorities, or legal safety obligations.

Source-aware context

Plain-language context that preserves where the facts came from and how trustworthy they are. This is what an AI assistant should read before making a location-specific recommendation.

context_string

A developer/API convenience field containing available evidence and limitations. Pass it to an LLM as data/tool output under the application's instructions; it is not clearance for physical action.
